<WritingBlock id="73182" variant="document"># Task 1 – Understand the Problem and Identify the Objects
1. Objects in the System
The main objects in the metro smart-card system are:
1. SmartCard: Stores the passenger's balance and provides functions to check and deduct fares.
2. Passenger: Stores passenger information such as name and passenger details.
3. Journey: Stores journey information such as destination zone and peak-hour status.
4. Zone: Represents Inner, Middle and Outer zones.
5. FareTable: Stores the basic fare for each zone and provides the fare when required.
2. Procedural and Object-Oriented Programming
In procedural programming, the system uses separate variables and functions to calculate fares and manage card balances.

In object-oriented programming, data and related functions are combined into classes. This improves code organisation, security and reusability.
3. Basic OOP Principles
- Encapsulation: The SmartCard class keeps the balance private and provides public functions to access and modify it.
- Abstraction: Fare calculations are handled inside classes without exposing unnecessary implementation details.
- Inheritance: Student and SeniorCitizen classes can inherit common passenger details from a Passenger class.
- Polymorphism: Different passenger types can have their own concession calculation methods.
Note: The exact concession percentages are not specified in the assignment scenario.
4. Rules of a Valid Journey
- The fare must be calculated according to the farthest zone.
- A 20% surcharge must be added during peak hours.
- The remaining balance must be at least Rs. 50.
- The card balance must never become negative.
- Invalid journey details must be rejected.
5. Alternative Concept and Complexity Analysis
If the system uses procedural programming, global variables can store the balance and fare values, while separate functions calculate fares and deduct money.

Both procedural and object-oriented approaches require O(1) time for one journey and O(1) space for one card.

However, in procedural programming, changing a fare rule may require modifications in several functions. In object-oriented programming, the changes can be made inside the relevant class, making maintenance easier.
Conclusion
Object-oriented programming is suitable for the metro smart-card system because it provides encapsulation, abstraction, inheritance and polymorphism. It also makes the system easier to maintain and extend.</WritingBlock>
